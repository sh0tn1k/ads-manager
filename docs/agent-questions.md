# Вопросы владельцу

Список ведётся по фазам. Ответы можно вписывать прямо сюда; значения, которые становятся конфигом,
задаются переменными окружения (`.env`) — имена указаны в скобках.

## A. Входные данные [ASK] (раздел 4 плана)

1. **Порог CPA** (`HURDLE_CPA_TON`) — максимально допустимая цена одного вступления в TON. Если
   привычнее в USD, нужен курс; в v1 порог хранится в TON. Без порога цикл предложений отвечает
   «предложений нет: не задан порог».
2. **Пул GEO** — файл `config/geo_pool.yaml`: коды стран и группировка по регионам (формат — в
   `config/geo_pool.example.yaml`, появится в фазе 4).
3. **Внешние размещения** (опционально) — `data/external_placements.csv` с колонками
   `channel_username,date,price_usd,joins,views`. Нужен как приор для таргета `channels`.
4. **Креативы** — фото и тексты, которые уже использовались; темы и слова, которые нельзя использовать.
5. **Лимиты**:
   - `EXPLORE_SHARE` (α) — доля свободного баланса на исследование за раунд;
   - `MAX_LOSS_PER_HYPOTHESIS` — максимальная потеря на одну гипотезу, TON;
   - `MAX_ACTIVE_EXPERIMENTS` — сколько тестовых объявлений одновременно;
   - `MAX_PENDING_PROPOSALS` — по умолчанию 3 (из плана);
   - `PROPOSAL_TTL_HOURS` — по умолчанию 12 (из плана);
   - `FIRST_LIVE_MAX_BUDGET` — бюджет первого живого объявления, TON;
   - `LLM_DAILY_USD_CAP` — суточный лимит на LLM, USD.

## B. Факты API, которые не закрыла документация [VERIFY]

6. **Семантика баланса.** `docs.html` описывает `remaining_budget` как «Remaining amount», а
   `ads_budget` как «Remaining amount … on advertisement budgets». Не сказано, входит ли второе в
   первое. Просьба запустить `python scripts/agent_recon.py` и прислать вывод (токен скрипт не
   печатает). До ответа используется консервативная формула (`AGENT_BALANCE_SEMANTICS=includes_ads`).
7. **Размещение для таргета `users`.** В документации таблицы `placement ↔ target.type` нет. В коде
   репозитория `users ↔ video_banner`. Какое размещение было у ваших прошлых объявлений с таргетом
   `users`? (Скрипт выше печатает эту таблицу.) Допустимы ли для `users` другие размещения, например
   `channel_post`?

## C. Расхождения плана и репозитория

8. **Кнопка для канала.** План (раздел 9) включает `button` в факторы. По `docs.html` кнопка
   «Applicable only if the URL you want to promote is an external link», а продвигается `t.me`-ссылка.
   Валидатор отклоняет `button` для `t.me`-ссылок. Если у вас кнопка для канала работала — сообщите.
9. **Существующие ручные пути изменения Ads.** В боте уже есть мастер `/create_ad`, кнопки паузы,
   бюджета и удаления, а также автостоп (`bot/watcher.py` сам ставит паузу по вашим правилам).
   Инварианты I1/I7 в коде соблюдены для `agent/`; старые ручные пути не тронуты. Оставить их как есть?
10. **Пустой allow-list.** В боте пустой `BOT_ALLOWED_USER_IDS` означает «доступ всем». Для принятия
    предложений (I1) пустой список означает «никому». Нужно задать свой Telegram user id.
11. **Резерв принятого, но ещё не созданного предложения.** Раздел 8 считает только резервы
    `proposed`. Чтобы два одновременных «Принять» не потратили один баланс, резерв держится до
    `created`/`failed` (то есть учитываются `proposed` и `accepted`). Возражений нет?
12. **Удалённые объявления в истории.** Бот хранит JSON сохранённых вручную объявлений
    (`data/library.sqlite`). Импортировать их в историю агента как источник для удалённых объявлений?
