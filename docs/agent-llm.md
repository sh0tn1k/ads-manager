# LLM-слой (фаза 5)

## Включение
LLM выключен, пока не заданы **все** значения: `LLM_MODEL`, `ANTHROPIC_API_KEY`, `LLM_DAILY_USD_CAP`,
цены `LLM_PRICE_INPUT_PER_MTOK`, `LLM_PRICE_OUTPUT_PER_MTOK`, `LLM_PRICE_CACHE_READ_PER_MTOK`,
`LLM_PRICE_CACHE_WRITE_PER_MTOK` (для ресерча ещё `LLM_PRICE_WEB_SEARCH_PER_1K`). Значения не угадываются:
`/propose` и `/budget` пишут, чего не хватает, и цикл работает без LLM.

## Устройство
- `agent/llm/provider.py` — интерфейс `LLMProvider` (`complete(LLMRequest) -> LLMResponse`).
- `agent/llm/anthropic.py` — Anthropic Messages API через httpx: вывод только через один инструмент
  со схемой (`tool_choice` = этот инструмент), prompt caching (`cache_control` на system и инструменте),
  веб-поиск `web_search_20250305` только в задаче research (там `tool_choice=any` и при необходимости
  финальный принудительный ход), продолжение `pause_turn`.
- `agent/llm/schemas.py` — строгие схемы (`extra=forbid`). В схемах нет полей promote_url, бюджета,
  CPM, таргета и инструментов, поэтому вывод модели не может их задать.
- `agent/llm/guard.py` — внешний контент оборачивается в `<untrusted_data>`, поддельные теги и
  управляющие символы вырезаются; проверки после схемы: ссылки и чужие @упоминания в тексте объявления,
  ссылки в поисковых запросах.
- `agent/llm/service.py` — `LLMService`: до `1 + LLM_MAX_RETRIES` попыток. В обратной связи модели
  передаются только места и типы ошибок, без значений. Каждый вызов (и неудачный) пишется в `llm_calls`
  с токенами, кешем, веб-поисками и стоимостью. Перед каждой попыткой проверяется
  `потрачено за 24 ч + худший случай попытки ≤ LLM_DAILY_USD_CAP`.

## Четыре задачи
| Задача | Вход | Выход | Использование |
|---|---|---|---|
| `research_hypotheses` | описание канала, сводка истории, разрешённые гео | запросы, приоры гео/тем (только направление), события, у каждого пункта URL-источники | поисковые кандидаты + сдвиги приора CTR ±0.3·уверенность |
| `generate_creatives` | прошлые тексты с реальными метриками | варианты текста (угол, длина, CTA, кнопка) | дополнительные креативы для history/grid; ранжирует реальный CTR, не LLM |
| `policy_check_and_fix` | текст + `decline_reason` | соответствие, проблемы, исправленный текст | готово для фазы 6 (правка отклонённых модерацией) |
| `explain_proposal` | факты без чисел | `rationale_ru` без цифр | пояснение в карточке; числа в карточке только из `model/` |

Источники ресерча должны совпадать с URL из результатов веб-поиска того же запроса, иначе вывод отклоняется.

## Безопасность
- `agent/llm` не импортирует `ads_api`, `executor`, `proposals`, `sync`, `bot` (тест в `tests/test_agent_layers.py`).
  Токен Ads API модели недоступен; ключ Anthropic уходит только в заголовке и вычищается из ошибок.
- Невалидный вывод не выходит из `LLMService`: цикл продолжает без него, предложения совпадают с режимом без LLM
  (тест `test_injected_llm_does_not_change_cycle_result`).
- Ключа в этой среде не было: все тесты на моках и ответах в формате API (`tests/fixtures/llm/`).
